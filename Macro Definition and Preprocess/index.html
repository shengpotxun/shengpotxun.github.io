Why we need macros?

In low-level development, macro definitions are absolutely not just simple “text replacements”; they are the core weapons for achieving cross-platform compatibility, system cropping, and extreme performance optimization.

For example, I have two esp32 board A and B with different hardware. And then I need to write thousands of if (a) else b to check this program is running on which one.What’s more CPUs need to do this stupid check a thousand times and memory needs to store a amount of useless imformation and wait CPU to tell it give up or not(Please bless memory is still alive.)

What if I use macro?The situation is completely different.

Defining the macro Board_A or not is the switch to control the code above. Only when I define Board_A the codes for it while be add to the files in preprocessing. If not, it will be physically deleted by the C Preprocessor before the compiler even starts. So CPU will not need to do too many judgements.

The Ultimate Metaphor

  • menuconfig is the Architect: It writes the blueprint (sdkconfig.h).
  • The Preprocessor is the Demolition Crew: It reads the blueprint and destroys any C code that doesn’t belong.
  • The Compiler is the Builder: It only builds what survives the demolition.
