static vs const vs define

Created2026-04-16|Updated2026-04-16|TechnologyC
|Word Count:550|Reading Time:3mins|Post Views:

int * const p vs const int * p

Try to read from right to left.

const always means read-only.

int * const p : p is a read-only point. So we can change something. For example, your name is Jack. I kicked your ass and your face is black and blue, but you are still Jack or p.

const int *p: p is a pointer which points a read-only variable(int). At this time, I can change the location but I can not kick your ass.

const vs static

OK, what about sattic? static always means lifelong and private.

  • In a function: The variable keeps its value even after the function ends (it doesn’t “die” on the stack).
  • Outside a function: It limits the variable’s scope to only that C file. Other files in your project cannot see it.

It will be stored in RAM.Now, the question is “how will a static pointer behave?”

First, it will be restricted to the file or function, even if where it points at is died.It’s like having a business card (the pointer) with an address written on it. Even if the building at that address is demolished (the variable a dies), you still have the card—but if you try to visit that address, you’re going to have a bad time.

In professional firmware, you will often see:

  1. static const uint8_t config_table[] = { ... };
    static: It hides the table from other .c files. This prevents “name collisions” (e.g., two different drivers both wanting a variable named config_table).
  2. const: It ensures the table is stored in Flash, saving your precious SRAM for dynamic tasks like Wi-Fi buffers or heap allocation.

The specified registers and the useful volatile

As what we have talked above,using a static pointer to point to a fixed hardware address (Memory-Mapped I/O or MMIO) is safe because hardware registers never “die” like local variables do.

However, there is a very specific way you should do this to ensure the compiler doesn’t accidentally break your code. When you point to hardware, you must use the volatile keyword.

If you don’t, the compiler might look at your code and say: “I already read this value once, and I don’t see any code changing it, so I’ll just reuse the old value.” But in reality, the hardware might have changed that value (e.g., a button was pressed).

vs. #define for I/O

Most HAL (Hardware Abstraction Layer) libraries use macros.

When you use a #define, the Pre-processor replaces the name with the value before the code is even compiled.

  • Pointer approach: The MCU has to go to a location in RAM, read the address stored there, and then go to that address. (2 steps)
  • #define approach: The address is baked directly into the machine code instructions (Immediate Addressing). (1 step)
